warnings.txt — triage ledger (the clang-cl/Windows warning list, FIXED)
=======================================================================

This file used to hold 796 lines of raw clang-cl output (216 warnings)
from a Windows build of the single-TU form. The README task list said
"#fix the warings"; this is what they were and what happened to each.

Triage
------
216 warnings total, exactly two kinds:

  215 x  -Wmicrosoft-include
          "#include resolved using non-portable Microsoft search rules"
          Every quoted #include in the tree resolved through -I dirs (or
          the MSVC include-stack rule) instead of the includer's OWN
          directory. Benign in effect (the -I flags did find the right
          file) but non-portable by construction, and the noise buried
          the one real warning below.

    1 x  -Wdangling-gsl
          src/minijz/apps/debugger.hpp:108 —
              const char *nm =
                  fid < P.fn_names.size()
                      ? std::string(P.fn_names[fid]).c_str() : "?";
          A std::string temporary's .c_str() stored into a pointer that
          OUTLIVED the full-expression: the printf one line later read
          freed memory (use-after-free, undefined behavior, "usually
          worked").

Fixes (all landed; ctest keeps them landed)
-------------------------------------------
1. Include portability, tree-wide: every quoted #include now resolves
   relative to the INCLUDING file's directory (standard search rule #1)
   -- 240 directives rewritten (e.g. "minijz/ir/instr.hpp" from
   prog/runners.hpp became "../ir/instr.hpp"). No compiler needs the
   -I flags for the compiler's own headers anymore; the flags stay as
   belt-and-braces. The -Wmicrosoft-include class is structurally
   impossible now: the warning can only fire when rule #1 FAILS, and
   rule #1 never fails.

2. The String/mjz_lib bridge (src/mjz_lib/alllib_import.hpp, checked in):
   graph_lib.hpp's "../mjz_lib/alllib_import.hpp" resolves through it via
   __has_include under BOTH upstream String layouts (clone-root and
   nested mjz_lib/mjz_lib/). This also killed the last -I-dependent
   include AND removed the two local-only symlinks the Linux sandbox
   used to need after a fresh clone.

3. The dangling-gsl: the frame-name pointer became a std::string that
   lives until the printf has consumed it (debugger.hpp "vm state"
   frame listing).

4. Sticky gate: ctest -R include_portability (label 'regr') walks every
   .hpp/.cpp under src/, tests/ and main.cpp and fails on any quoted
   include that does not resolve in its includer's directory --
   reintroducing the warning class now fails the battery.

Regenerating a fresh list on Windows
------------------------------------
  cmake --preset vs-clang
  cmake --build build-vs
  (or the plain clang-cl/nmake line from a Native Tools prompt)
Everything but toolchain-internal noise should come back empty; if a
new warning appears, add it to this ledger with its fix.
